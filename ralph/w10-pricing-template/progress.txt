## Codebase Patterns
- The workstream DB is `atelier_w10` (set in `atelier-api/.env`). It was already migrated to
  `1786248000000_trade-accounts` at the start of this workstream, so a new migration is the only
  thing `npm run migrate` applies.
- `psql` is not runnable from this harness (permission denied). To inspect the schema, run
  `node -e "..."` from `atelier-api/` — CommonJS `require('dotenv')`/`require('pg')` resolves off the
  cwd's node_modules, whereas an ESM script in the scratchpad cannot resolve the package at all.
- Compound Bash commands with `&&` chains and `head`/`grep` can be denied by the permission layer.
  Run one command per call.
- node-pg-migrate names an inline column `check:` constraint `<table>_<column>_check`. To widen one,
  `pgm.dropConstraint(table, '<table>_<column>_check')` then `pgm.addConstraint(...)` with the same
  name — do not invent a new name or the next migration cannot find it.
- A Postgres CHECK is satisfied by NULL (unknown, not false), so a `~ '^[A-Z]$'` check on a nullable
  column still lets the column stay empty. That is what makes widening the class checks safe for the
  19.5k existing rows.
- `npm test` runs 37 files / 603 tests against the real local Postgres in ~22s. `fileParallelism:
  false` is load-bearing — do not touch it.
- **`incoming/pricing-templates/` does NOT exist in this worktree** — `incoming/` is gitignored, so
  the corpus lives only in the main checkout, which the sandbox refuses to read. `npm run
  convert:pricing` therefore cannot be run here at all, and the project-context gate
  `npm run convert:pricing && git diff --exit-code src/seed/data/price-lists.json` is
  unrunnable in this workstream. Byte-identity must be argued by construction (move code, do not
  rewrite it) and proved with a hand-made fixture converted to a scratchpad path — never to the
  committed JSON.
- A converter run against a scratch fixture is the cheap end-to-end check: `node
  scripts/convert-price-lists.js <scratch-in-dir> <scratch-out.json>`. The filename must match
  `^(.+?)(?:\s+(FABRIC|WPPR|TRIMMING))?\s+PL\b`, e.g. `PIERRE FREY PL.csv`, for any template
  WITHOUT its own Supplier column (v1); since US-003 a v2 fixture may be named anything.
- `npm run lint` and `npm test` run fine as `cd atelier-api && npm run <script>`; a bare `npx
  vitest run <file>` is denied by the permission layer, so run the whole suite.
- A newer template maps by DELEGATING to the older mapper, never by re-listing its columns:
  `mapV1` already reads only its own first N cells, so `mapV2(row)` calls `mapV1(row, ...)` and
  spreads the result. That is what keeps the shared columns byte-identical by construction rather
  than by review.
- Adding a key to a converter's output means auditing whatever compares two output rows.
  `sameExceptSource` iterated only the FIRST row's keys, so a richer row would have been silently
  dropped as an exact duplicate of a thinner one. Compare key COUNTS too.
- **`src/seed/price-lists.js` builds its dedupe key with a literal NUL byte, not a space**
  (`${supplier}\0${category}\0${code}`). The Read tool renders NUL as a space, so an exact-match
  edit anchored on that line ALWAYS fails with "String to replace not found". `sed -n 'N,Mp' <file>
  | cat -et` shows it as `^@`. Anchor edits on a neighbouring line instead. Other files may hide the
  same thing — an unexplained failed match is the tell.
- To give an `unnest` batch a per-column expression (a COALESCE, a cast, a default), NAME the
  rowset: `SELECT COALESCE(b."col", 'x'), b."other" FROM unnest($1::text[], ...) AS b("col",
  "other")`. `SELECT *` cannot wrap a single column. The alias list takes the same quoted names, so
  it is generated from the same `COLUMNS` array and cannot drift out of order.
- A validator can be strict about TYPE and silent about RANGE, and that is often the correct pair:
  the type is knowable now, the legitimate range is a client decision nobody has made. Say so in a
  comment at the check, or the next person adds the guess back.

- **Learnings:**
  - Patterns discovered (general and reusable):
    - node-pg-migrate's inline column `check:` produces `<table>_<column>_check`; widening means
      drop-then-add under the SAME name.

      four new columns, so `importPriceLists` writes none of them. That is why the US-001 schema
      tests insert with raw SQL. When US-004 adds `template_version` to `COLUMNS`, it MUST be
      `COALESCE($n, 'v1')`-style in the SELECT — `unnest` binds an explicit NULL for a missing key

    - `template_version` has no CHECK deliberately; the accepted set lives in the code registry
      (US-002). Do not add one — it would make every new template a migration.
    - `duty_percent` is unconstrained beyond `numeric(6,3)`: no legitimate range has been given, and
      a guessed CHECK is the same class of mistake as the old freight letter set.
  - Context (where the relevant code lives):

## 2026-08-06T15:00:00Z - W10-US-002 - Template registry with v1 moved verbatim

  is untouched (`git status` clean for it).
- **Learnings:**
  - Patterns discovered (general and reusable):
    - Moving code to make it extensible is only safe if it is MOVED. `mapV1` was copied
      character-for-character including its comments; the only edit was `COLUMNS` ->
      `V1_HEADER.length`. Anything reworded while moving cannot be argued to be byte-identical.
    - Converting a hand-made fixture to a scratchpad path and eyeballing it against a line of the
      committed output is a real byte check that costs nothing and touches no committed file.
  - Gotchas (what will bite the next iteration):
    - **The old header check sliced to 14 columns before comparing**, so a header with extra
      columns matched v1 by its first 14. That had to stop — a v2 file starts with v1's 14 columns
      and would otherwise be silently imported as v1. `matchTemplate` is exact on length, and the
      15-column `v1 + Supplier` header now fails loudly (verified). US-003 makes that same header
      match v2 by adding the second registry entry.
    - **`normaliseHeader` deliberately drops TRAILING EMPTY cells before matching.** A CSV header
      line ending in a comma yields a 15th blank field, and Excel emits blank cells too; counting
      one would have failed a real drop over a stray comma. A blank cell declares no column, so it
      cannot disambiguate two templates — a NAMED extra column still changes the length and still
      fails. This tolerance was chosen because the corpus is unreadable from this worktree and the
      strict rule could not be tested against it; if a real drop ever fails on its header, this is
      the first place to look.
    - The corpus cannot be read from this worktree at all (see Codebase Patterns), so
      `npm run convert:pricing` is not a gate anyone can run here. US-003's "byte-identical
      price-lists.json" criterion has to be met by construction plus US-006's unit-level byte pin.
    - `FREIGHT_CLASSES`/`DUTY_CLASSES` moved verbatim and are still the narrow sets (`A`–`E`, `A`).
      They are now in `price-template.js`, which is where US-005 wants the shared vocabularies —
      but they are still private to that file. US-005 exports them.
  - Context (where the relevant code lives):
    - Registry + v1 mapper: `scripts/lib/price-template.js`. Its tests: `test/price-template.test.js`.
    - File walk, supplier name, dedupe, write: `scripts/convert-price-lists.js`.
    - Shared machinery it leans on: `scripts/lib/{xlsx,text,python-format}.js`.
    - Rationale: `_bmad-output/planning-artifacts/architecture.md` "## Pricing template".
- **Needs human verification:** none — no screen renders anything from this change; the converter
  is a CLI. What a human SHOULD do before merge, because this loop cannot: run
  `npm run convert:pricing && git diff --exit-code src/seed/data/price-lists.json` on a checkout
  that has `incoming/pricing-templates/`, which proves both the byte-identity and that no real
  drop's header row is rejected by the now-exact length match.

## 2026-08-06T15:20:00Z - W10-US-003 - v2 mapping and the omit-on-v1 rule
- Registered v2 in `scripts/lib/price-template.js`: `V2_HEADER` is v1's fourteen labels plus
  `supplier`, `brand`, `pattern match`, `duty percent` in that order, and `mapV2` delegates the
  shared cells to `mapV1` (which reads only its own first 14) then appends `brand_name`,
  `pattern_match`, `duty_percent` and `template_version: 'v2'`. The Supplier CELL wins over the
  filename (blank falls back to it; neither present fails the row `file:line: empty supplier ...`).
  `duty_percent` is `round3(parseNumber(...))` — the scale of `numeric(6,3)`, so the JSON says what
  the database will hold — with NO range check, and a non-numeric cell fails the row loudly.
  `mapV1` is unchanged apart from a comment at its return stating why v2 keys are omitted, never
  written as null. The converter now treats the filename as a FALLBACK: `parseFilename` returns
  nulls instead of throwing, and a template with no Supplier column plus an unreadable filename is
  a loud per-file error. `sameExceptSource` now compares key counts as well.
- Repos and files changed (atelier-api only):
  - `scripts/lib/price-template.js` (+~55 lines: `V2_HEADER`, `round3`, `failRow`, `mapV2`, entry)
  - `scripts/convert-price-lists.js` (filename fallback, the v1-needs-a-name error, dedupe guard)

    and the mapV1 omission rule asserted directly)
  - `_bmad-output/implementation-artifacts/sprint-status.yaml`, `ralph/w10-pricing-template/prd.json`,
    `ralph/w10-pricing-template/progress.txt`, `CLAUDE.md`
- Gates: `npm run lint` -> 0, `npm test` -> 0 (37 files, 593 tests passed). Plus three converter
  runs against scratchpad fixtures, all writing to scratch paths only:
  - v1 fixture -> a record with the same key order, `", "` separators and `115.0` float repr as
    line 2 of the committed JSON, and NONE of the four v2 keys.
  - v2 fixture named `universal template 2026.csv` (deliberately unparseable) -> two rows, two
    DIFFERENT suppliers from one file, `duty_percent: 7.5`, `template_version: "v2"`, blank cells
    as nulls.
  - the same v1 rows under an unparseable name -> `rates 2026.csv:1: cannot derive supplier from

- **Learnings:**
  - Patterns discovered (general and reusable):
    - A superset template's mapper should delegate to the older one, not re-declare the shared
      columns. `mapV1` bounds its own read to `V1_HEADER.length`, so passing it an 18-cell row is
      already correct; overriding one input (the supplier) is `mapV1(row, { ...context, supplier })`.

      .includes('supplier')` — so the converter needs no per-template flag.
  - Gotchas (what will bite the next iteration):
    - **`mapV2` emits `template_version: 'v2'` and `mapV1` emits no such key at all.** US-004 must

    - `validatePriceListItems` (`src/seed/price-lists.js`) does not yet know the four new fields,

      That is US-004's whole job.
    - `mapV2` inherits v1's narrow `FREIGHT_CLASSES`/`DUTY_CLASSES` (`A`–`E`, `A`) because it
      delegates — so widening them in US-005 widens both templates at once, which is the intent.
    - `duty_percent` is rounded to 3dp; if a real file ever carries a value ≥ 1000 it will pass the
      converter and overflow `numeric(6,3)` at import. Not guarded on purpose — no legitimate range
      has been stated and guessing one is the mistake the old freight-class set already was.
    - The converter no longer ABORTS on an unreadable filename; it reports and keeps collecting, so
      one bad name no longer hides every other error in the drop. Still writes nothing.
  - Context (where the relevant code lives):
    - Registry, both mappers, header matching: `scripts/lib/price-template.js`.
    - File walk, filename fallback, dedupe, write: `scripts/convert-price-lists.js`.
    - Importer that must catch up: `src/seed/price-lists.js` (`validatePriceListItems`, `COLUMNS`).
    - Rationale: `_bmad-output/planning-artifacts/architecture.md` "## Pricing template".

## 2026-08-06T15:40:00Z - W10-US-004 - Importer accepts the v2 fields
- Taught `src/seed/price-lists.js` the four v2 columns. `validatePriceListItems` now checks
  `brand_name`, `pattern_match` and `template_version` with a new `optionalText` helper (absent or
  null is normal — every v1 row omits them — but a present value must be a non-empty string), and
  `duty_percent` is type-checked only (`Number.isFinite`) with NO range, commented as such. All four
  joined `COLUMNS`, so `unnest` now binds them; `duty_percent` joined `wholesale_rate` in a new
  `COLUMN_TYPES` map as `numeric` (the 3-deep ternary would not have taken a third entry legibly).
  The upsert SELECT is no longer `SELECT *`: the rowset is aliased `AS b(...)` so
  `template_version` can be `COALESCE(b."template_version", 'v1')` — an `unnest` batch binds an
  explicit NULL for a key a v1 item does not carry and that NULL defeats the column's
  `NOT NULL DEFAULT 'v1'`. The upsert key `(supplier, category, code)` and the set-everything-to-
  EXCLUDED contract are untouched.
- Repos and files changed (atelier-api only):
  - `src/seed/price-lists.js` (+~45 lines: `optionalText`, four validations, four columns,
    `COLUMN_TYPES`, `SELECT_LIST`, the aliased unnest)

  - `_bmad-output/implementation-artifacts/sprint-status.yaml`, `ralph/w10-pricing-template/prd.json`,
    `ralph/w10-pricing-template/progress.txt`, `CLAUDE.md`
- Gates: `npm run lint` -> 0, `npm test` -> 0 (37 files, 603 tests passed; was 593). Plus a real
  end-to-end seam check: a two-row v2 CSV fixture converted to a scratch path with

- **Learnings:**
  - Patterns discovered (general and reusable):
    - An `unnest` batch needs a NAMED rowset (`AS b(cols…)`) the moment any one column needs an

      two cannot drift.
    - Validate type strictly, leave range alone where no range has been stated — and comment the
      omission at the check so it is visibly deliberate rather than forgotten.
  - Gotchas (what will bite the next iteration):
    - **The dedupe key in `validatePriceListItems` is joined with literal NUL bytes**, which Read
      renders as spaces; editing that exact line by string match is impossible until you anchor
      elsewhere. Cost one failed edit here — see Codebase Patterns.
    - **A later v1 file for a key already imported from a v2 one CLEARS its v2 fields** and sets
      `template_version` back to `'v1'`, because every non-key column is still `= EXCLUDED`. That is
      this table's freshest-wins contract applied uniformly, not an oversight; it is asserted by a
      test and commented above `UPSERT_SQL`. Adding a quieter COALESCE rule for just these columns
      would be a product decision.
    - `template_version` is deliberately NOT enum-checked in the importer. The accepted set is the
      converter's registry, so an older API importing a newer converter's file must still store the
      row. US-005 moves the OTHER vocabularies into `price-template.js` — do not sweep this one in
      with them, and note that `src/seed/price-lists.js` cannot import from `scripts/` anyway.
    - `FREIGHT_CLASSES` (`A`–`E`) and `DUTY_CLASSES` (`A`) in `src/seed/price-lists.js` are STILL
      narrower than the DB check (`~ '^[A-Z]$'`), and `test/price-lists.test.js` still asserts
      `freight_class: 'Z'` is rejected. Untouched here on purpose — US-005 owns the vocabularies and
      must update that `it.each` row in the same change.
    - `duty_percent` >= 1000 passes validation and overflows `numeric(6,3)` at the INSERT. Loud, and
      intentional: no legitimate range has been stated.
  - Context (where the relevant code lives):
    - Validator, `COLUMNS`, `UPSERT_SQL`: `src/seed/price-lists.js`. CLI: `src/seed/import-price-lists.js`.
    - What the converter emits: `mapV1`/`mapV2` in `scripts/lib/price-template.js`.
    - Schema: `migrations/1786334400000_price-list-template-v2.js`.
    - Tests: `test/price-lists.test.js` (import behaviour + the schema block from US-001).
