# Ralph progress log — Atelier — August 6th updates — W6 Category export

## Codebase Patterns

General, reusable findings only. A Ralph iteration reads this block FIRST, before anything else.
Story-specific detail belongs in the per-story entries below, not here.

- **`src/` and `scripts/` may import each other freely** — one package, plain relative specifiers,
  no bundler, no `files` field. `src/seed/price-lists.js` already imports `scripts/lib/price-template.js`;
  `scripts/lib/text.js` now imports back the other way. A shared module belongs wherever its owner
  lives, and the other side re-exports.
- **`incoming/pricing-templates/` does not exist in a worktree** (gitignored, main checkout only),
  so `npm run convert:pricing` cannot run here at all and the byte-identity gate cannot be run as
  written. Verify a converter-adjacent change with a hand-made fixture instead:
  `node scripts/convert-price-lists.js <in-dir> <out.json>`, filename matching
  `^(.+?)(?:\s+(FABRIC|WPPR|TRIMMING))?\s+PL\b`, then compare the emitted record against the
  matching line of the committed `src/seed/data/price-lists.json` (line 2 is its first record;
  strip the trailing comma). `test/price-template.test.js`'s byte-pin block names the exact cells
  behind that line.
- **`atelier_w6` was seeded AFTER `1786593600000_featured-rank` ran**, so the migration's UPDATE
  matched nothing and `test/featured-rank.test.js` failed on a database defect, not on any code.
  Repaired once by running the migration's own exported `brandFeatureSql`/`collectionFeatureSql`
  against the seeded rows (a migration may export more than `up`/`down`, and here that is what
  makes the repair the exact statement rather than a retyped copy). If a featured assertion fails
  again after a reseed, this is why — do not chase it into `src/`.
- **A W6 gate run is both repos** even for an api-only story: `( cd atelier-api && npm run lint && npm test )`
  and `( cd atelier-crm && npm test && npm run build )`. The CRM has no ESLint, so `build` is its
  only compile check.
- **A new route plugin has to be registered in `src/app.js`, and that file is nobody's exclusive
  property.** It is not on W6's MUST-NOT list, and a route file no `api.register` line names is
  dead code — so the edit is one import plus one registration, appended, never a restructure. Every
  workstream adding a route makes the same two-line change, so keep it additive and adjacent to
  the existing block or the human merge turns into a conflict for no reason.
- **`npm test -- <file>` and `npx vitest` are both blocked at the tool level here; `npm test` is
  not.** Budget for the whole suite (~33 s, 52 files) on every check rather than trying to narrow
  it — the narrowing attempt costs a denied call and tells you nothing.
- **Ajv applies a querystring `default` only when the key is ABSENT.** `?brand=` sends the empty
  string, which is present, so it meets the `pattern` instead and 400s. That is the right answer
  for an export (the caller asked for a house and named none) and the opposite of the CRM list
  rule, where `buildListQuery` drops an empty filter precisely so it never reaches the API.

  `npm test` (atelier-crm) -> 0 (37 files, 567 tests), `npm run build` (atelier-crm) -> 0.
- Byte identity: `npm run convert:pricing` cannot run in a worktree (`incoming/` is gitignored and
  absent). Proved instead with a hand-made `ALTAGAMMA WPPR PL JUNE 2026.csv` carrying the v1 header
  and the cells behind the committed file's first record: the converter's output line is byte-for-byte
  equal to line 2 of `src/seed/data/price-lists.json`. That file is unmodified.
- **Learnings:**
  - The re-export is deliberately not "update every caller": leaving the specifiers alone is what
    lets `test/converters.test.js` stand unchanged as the proof this was a move. A future story that
    wants the direct path can import `src/lib/csv-text.js` without disturbing the converters.
  - `decodeText` takes a Buffer (it falls back to `bytes.toString('latin1')`), not a Uint8Array —
    the upload path in US-003 must hand it the raw Buffer Fastify gives it.
  - `csvRows` yields `[lineNumber, fields]` with `lineNumber` 1-based and counting the header, so a
    row-number in a validation error is that number directly, with no offset arithmetic.
  - Context: the pricing converter is `scripts/convert-price-lists.js` over `scripts/lib/`; the
    accepted header layouts and every shared vocabulary live in `scripts/lib/price-template.js`.
- **Needs human verification:** none — no route, no screen and no data file changed.

## 2026-08-06T18:40:00Z - W6-US-002 - Product sheet export with an empty Category column
- `GET /admin/product-sheet/export.csv?brand=<slug>` (backoffice-only, director inherits) downloads
  one house's products as a fill-in sheet. Header contract, in order:
  `Product ID,House,Collection,Design,Category`. `Product ID` is `products.id` — the stable server
  key, so US-003's re-import matches on identity and never on row order. `Category` is emitted
  EMPTY for every row.
- The hardened CSV writer is now `csvCell`/`csvRow`/`csvDocument` in `src/lib/csv-text.js`, beside
  the reader US-001 put there: formula lead-ins (`= + - @ TAB CR`) get an apostrophe, RFC 4180
  quoting for quote/comma/newline, CRLF separators, trailing newline. Epic 6 allows "E5 US-001 (the
  CSV writer) or its own extraction" — W5 is not merged into this branch and `src/reports/**` is
  W5's, so this is the own extraction.
- Repos and files changed: atelier-api — `src/lib/csv-text.js` (writer half added),
  `src/products/product-sheet.js` (new), `src/routes/admin-product-sheet.js` (new), `src/app.js`
  (import + one `api.register` line), `test/product-sheet.test.js` (new, 20 tests), `CLAUDE.md`
  (`## Category export`), `ralph/w6-category-export/{prd.json,progress.txt}`,
  `_bmad-output/implementation-artifacts/sprint-status.yaml`.
- Gates: `npm run lint` (atelier-api) -> 0, `npm test` (atelier-api) -> 0 (52 files, 1185 tests),
  `npm test` (atelier-crm) -> 0 (37 files, 567 tests), `npm run build` (atelier-crm) -> 0.
- **Learnings:**
  - The empty Category column is not a simplification, it is what makes US-004's counts possible:
    exporting the stored value would leave a re-import unable to tell "the office confirmed this"
    from "the office did not touch this row". Blank must therefore mean *skipped* in US-003/US-004,
    and a value equal to the stored one must count as *unchanged*.
  - `src/pricing/trade-price-lists.js` still carries its own copy of the same two cell rules. It is
    outside W6's writable set and nothing about the trade list changed, so it was left alone; the
    new module says so in a comment, and whoever next touches that file should import from
    `src/lib/csv-text.js`. Do NOT "tidy" it in a W6 story.
  - A test asserting the DEFAULT brand cannot assume the seed: CI runs migrations only, so
    `atelier-textiles-nz` may not exist. Assert instead that the no-`?brand=` response EQUALS the
    `?brand=atelier-textiles-nz` one — true at 200 and at 404 alike — plus a direct assertion on
    the exported `DEFAULT_BRAND_SLUG` constant.
  - `csvCell('=HYPERLINK("x")')` is `"'=HYPERLINK(""x"")"`, not `'=HYPERLINK…`: the quote in the
    payload triggers RFC-4180 quoting on top of the neutralisation. A `startsWith("'=")` assertion
    fails on the writer being MORE correct, which cost one red run here.
  - Archived products are excluded from the sheet and hidden (`show_on_website = false`) ones are
    included — a back-office sheet, so a design still being photographed is exactly the kind nobody
    has categorised yet. A house with no products is a header-only file, not a 404; an unknown slug
    IS a 404.
  - Context: the header contract and the query live in `src/products/product-sheet.js`; the four
    legal values are `products.category`'s CHECK (`migrations/1786507200000_product-category.js`),
    shared verbatim with `price_list_items.category`, and are deliberately NOT printed in the file —
    a CSV has nowhere to put a note Excel will not hand back as a data row. US-005's panel states
    them and US-003 reports an unknown one with its row number.
- **Needs human verification:** no screen exists yet (US-005 builds it), so a person should
  download the sheet once from a signed-in back-office session — e.g.
  `http://localhost:3001/admin/product-sheet/export.csv?brand=atelier-textiles-nz` — open it in
  Excel and confirm it opens as five columns with an empty Category, and that a design named
  `=cut to order` shows as text rather than evaluating.
