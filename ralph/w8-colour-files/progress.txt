# Ralph progress log — Atelier — August 6th updates — W8 Colour files

## Codebase Patterns

General, reusable findings only. A Ralph iteration reads this block FIRST, before anything else.
Story-specific detail belongs in the per-story entries below, not here.

- **A worksheet is addressed by NAME, never by `sheet<N>.xml`.** The number in the filename is the
  order the sheets were CREATED in, not the order they appear in, and one file in this corpus
  (C&C Milano) has a single sheet called `sheet.xml` with no number at all. Resolve
  `xl/workbook.xml` -> `xl/_rels/workbook.xml.rels` by relationship id. A rels `Target` may be
  relative to `xl/` (`worksheets/sheet1.xml`) or absolute from the package root
  (`/xl/worksheets/sheet.xml`) — handle both.
- **The `x:` namespace prefix is not a D365 quirk.** CLAUDE.md records it for D365's `<x:row>`;
  C&C Milano's supplier-written workbook root is `<x:workbook>` too. Anything scanning
  SpreadsheetML by tag name must resolve the prefix via `namespacePrefix()` first. Matching a bare
  tag name silently finds nothing, which reads as "empty workbook", not as a parser bug. The same
  applies to the ATTRIBUTE prefix: `r:id` comes from `xmlns:r="…/relationships"`, so resolve it
  from the declaration rather than assuming the letter.
- **`scripts/lib/` is dependency-free by design and stays that way.** `zip.js` + `xml.js` +
  `xlsx.js` are enough to read any of these workbooks; `node_modules` is a symlink to the main
  checkout, so adding a package corrupts every other worktree on this machine.
- **`incoming/` is gitignored, so no test may read it.** Build a real xlsx in memory instead: a
  genuine deflated zip (`deflateRawSync`) of genuine SpreadsheetML. `test/converters.test.js`
  already had the `buildZip` helper; `test/colour-files.test.js` carries its own copy because the
  converters test is another workstream's file.
- **A supplier's own spelling of a house is not the catalogue's, and the file must never invent
  one.** "Mariaflora" is `Maria Flora`, "Liberty" is `Liberty London`, and the same trap is already
  recorded for the price lists ("Colefax & Fowler" vs "Colefax and Fowler"). Map the ones you can
  evidence in a declared alias table, pass an unknown spelling through raw, and let the import
  report it — a house created silently is the one outcome nobody can undo.
- **The price list is the corpus that identifies an unlabelled code prefix.** `src/seed/data/
  price-lists.json` holds 19.5k rows across 40 suppliers with their `code` and `product_range`, so
  a mystery token can be looked up rather than guessed: `NH-AFTERALLTOO` in there under supplier
  "Nicky Haslam" is what identified the `NH` sheet of the Jean Monro workbook. When nothing in it
  matches, that is an answer too — emit the token and let a human name the house.
- **The price list also verifies a DERIVED code, not just an unlabelled one.** Nine of these files
  print a colourway SKU that is the design's code plus a colour suffix (`F4613-01`, `6978401`,
  `JT013998001`), and the design part is exactly what `price-lists.json` keys on. Splitting the SKU
  and looking the prefix up in that supplier's own rows turns the split rule into a measurement:
  Colefax 9,015 of 9,065, Jim Thompson 2,839 of 3,320 (the other 481 are Fox Linton, which has its
  own supplier rows), the five Fabricut houses 97%+ each. A rule that cannot be measured this way
  is a guess, and the corpus usually offers a way to measure.
- **A row that is not stock is not the same as a row that failed to map.** Every large file carries
  non-stock rows mixed into its stock sheets — sample books and colour cards (JV, 239 rows, told
  apart only by the sales unit), sample cuttings (C&C Milano's 587 `Camp.` rows, told apart by a
  type code), a translation dictionary (C&C Milano rows 2-4), a substrate price table (CO.DE, 45
  rows with no item code). A mapper DECLINES those by a stated, measured property and THROWS on
  anything else it cannot map. Importing them puts a sample book in the catalogue as a colourway;
  throwing on them fails a file that is perfectly well formed.
- **A DECLINED row must state WHY, and the reason names a KIND of row, not that row.** A summary
  reading "1,604 rows skipped" is a number nobody can account for; "587 sample cutting, 262 sample
  sold by the unit, 45 substrate price, 684 blank" is a file someone can check. `skip(reason)` in
  `colour-adapters/records.js` is the mechanism, and a decline with no reason still lands in its own
  counted bucket rather than vanishing — rows in ALWAYS equals colourways out plus skips plus errors,
  which is what makes the summary auditable at all.
- **Collect every bad row, do not stop at the first.** A supplier who renamed one column usually
  renamed three, and a converter that dies on the first one is fixed one release per row. The reader
  yields a bad row as data (`{ rowNumber, error }`) and the caller decides; the strict view over it
  still throws, so a caller that only wants records cannot walk past one. Same for a sheet that will
  not open: record it and read the remaining eight.
- **Loud failure means the WHOLE run writes nothing, not just the bad file.** A half-written
  catalogue is worse than none — the missing houses look exactly like houses the supplier stopped
  carrying. Both existing converters have this posture; keep it.
- **An exact repeat is dropped; a CLASH is reported and both rows kept.** 1,159 of the 47,082
  colourways are exact repeats (Liberty's overlapping sheets, Jim Thompson's spring subset, Maria
  Flora's 73 reprints) and dropping them is safe because nothing is chosen. Seven rows share a
  (house, design, colour code) with a DIFFERENT name — the supplier's own two spellings ("Blue
  Grass"/"Bluegrass", "Lino"/"Linen") — and dropping one of those is choosing, on an identity key
  nothing has ratified. Report and keep.
- **A converter whose output lands in its own input directory must filter directories out of the
  walk.** `readdirSync(dir, { withFileTypes: true })` + `isFile()`: otherwise the second run meets
  the `normalized/` directory it wrote and reports it as a drop nobody has mapped.
- **A second output belongs in a shape the office already ratified, not in one of its own.** The
  colour files are price lists too, and `scripts/lib/price-template.js` already defines what a
  supplier rate looks like — so the rate output IS the v2 template (a CSV with its header row),
  which puts it through `convert-price-lists.js`'s vocabularies, code normalisation, dedupe and
  importer instead of a second private path. The header is asserted against `matchTemplate` at
  module load, and every emitted row is run through the template's own mapper before the file is
  written, so "it is in the template's shape" is a measurement rather than a claim.
- **A SECTIONED sheet reprints its header with some columns RENAMED, and often SHIFTED.** Liberty's
  wallpaper section writes `WALLPAPER NAME`/`PAPER TYPE` and inserts `ROLL DIMENSIONS` after the
  width, so every later cell moves by one; Madeaux relabels its price column per section
  (`Export/m`, `Export/ Roll`, `Export`). Two consequences: the shared "row repeats the header" rule
  does not recognise such a row (declare it by the one label that does not change), and no column
  past the first divergence may be declared at all — a composition read at the wrong index is a
  repeat measurement filed as a fibre content, which nothing downstream can detect.
- **The committed price list is the corpus that verifies a whole extraction, not just a code.**
  Every emitted rate can be looked up by `(supplier, category, code)` in `src/seed/data/
  price-lists.json`: 14,914 of 15,611 land on a row the office already holds and 10,634 of those
  are identical to the cent. That turns supplier naming, code grain, category and unit into
  measurements — and it is how the JV dealer-price factor and Liberty's two price columns were
  settled. A rule nobody can measure this way is a guess.
- **`(supplier, category, code)` is a ratified key, so two rates under it are not a clash to report
  — they are a rate nobody may write.** Unlike a colourway clash (both rows kept, because the SKU's
  shape is still the import's decision), the ledger holds exactly one row per key. Keeping the
  first decides silently and keeping both makes the pricing converter refuse the whole file, so the
  code gets NO rate and every coordinate is printed. 230 of 15,841 codes end up there.
- **Verify a derivation against the file's own redundancy before shipping it.** Several of these
  sheets decompose a value into extra columns they then leave blank further down (Jean Monro splits
  its item codes across three unlabelled cells for the first 102 rows of one sheet and none of the
  last 50). Deriving the value and diffing it against those cells over the whole file turns "this
  regex looks right" into a measurement — and the rows where the file stopped filling them in are
  exactly the rows the derivation exists for.

## 2026-08-06T16:05:00Z - W8-US-001 - Adapter registry and the row-extraction harness

- **What was implemented**
  - `scripts/lib/colour-sheet.js` — the shared row-extraction harness. Resolves sheet name -> zip
    path, yields dense rows, and LOCATES THE HEADER ROW BY MATCHING LABELS within a bounded scan
    window (`HEADER_SCAN_LIMIT = 250`). The adapter's column map IS the label set the header is
    recognised by, so the map and the recognition rule cannot disagree. `select(cells)` returns the
    declared fields of a row, trimmed.
  - `scripts/lib/colour-adapters/index.js` — the registry keyed by filename prefix, with
    `assertAdapter`/`assertRegistry` running at import over every entry, `selectAdapter` (pure,
    longest-prefix-wins) and `matchAdapter`. An entry may declare itself `unsupported` with a
    reason — deliberately distinct from an unknown filename.
  - `scripts/convert-colour-files.js` + `npm run convert:colour` — the harness driver. Walks the
    drop directory, resolves an adapter per file, opens every declared sheet and reports
    `file:sheet: header row N, M data row(s)`. A DECLARED refusal is reported and is not fatal; an
    UNKNOWN file is listed on stderr and exits 1. It writes no output file — the normalised write
    is US-004's, and the header comment says so.
  - `test/colour-files.test.js` — 22 tests, no database, no fixtures on disk.
- **Repos and files changed** — atelier-api only:
  `scripts/lib/colour-sheet.js` (new), `scripts/lib/colour-adapters/index.js` (new),
  `scripts/convert-colour-files.js` (new), `test/colour-files.test.js` (new),
  `package.json` (scripts only), `CLAUDE.md` (new `## Colour files` section).
- **Gates:** `npm run lint` -> 0, `npm test` -> 0 (41 files, 771 tests, 22 new).
- **Learnings:**
  - Patterns (general ones are also in `## Codebase Patterns` above):
    - The registry deliberately separates DECLARED-unsupported from UNKNOWN. A declared refusal is
      a decision someone recorded (the de Le Cuona PDF, US-003); an unknown filename is a drop
      nobody has looked at and must fail the run, because a skipped file looks exactly like a file
      that imported cleanly.
    - `selectAdapter(adapters, filename)` takes the registry as an argument and `matchAdapter`
      binds it to `ADAPTERS`. That is what let the longest-prefix rule be tested while the registry
      is still empty — the alternative (re-implementing the rule in the test) asserts nothing.
    - A duplicated label is only an error on a row that OTHERWISE matches. Checking earlier would
      make any preamble row carrying two blank-ish repeats abort the file.
  - Gotchas for the next iteration:
    - **Measured header rows, so no adapter has to rediscover them:** C&C Milano/Listino 1,
      Colefax/Export Prices 1, JV/(all ten sheets) 1, Jean Monro/JM 1, Jim Thompson 2026/CODE LIST
      1, Maria Flora/Foglio1 1, Pierre Frey 1; Jim Thompson SS'26/FABRIC 2, Liberty/Sheet1 2,
      Madeaux/UK Export 2; Perennials WC/ALL SKUS 3; Perennials Fabrics/Fabrics 4;
      Vervain/All Colors 77, Clarence House/All Colors 98, S Harris 104, Trend 105, Stroheim 106.
      Clarence House's *Pattern Only* sheet is 102. Row numbers count `<row>` elements from 1 — a
      position in the file, not the spreadsheet's row label.
    - **`sheetRows` skips no rows but omits empty cells**, so a data row can be SHORTER than the
      header. `select` reads an absent cell as `''`, never `undefined` — do not `.trim()` a raw
      `cells[i]` yourself.
    - The five US houses (Clarence House, S Harris, Stroheim, Trend, Vervain) are the same layout
      with the same terms preamble and a `Pattern Only` + `All Colors` sheet pair. `All Colors` is
      the colourway sheet; `Pattern Only` has no colour column at all. That is one adapter shape
      reused five times in US-003, not five adapters.
    - Jean Monro's `JM` sheet has THREE sheets (JM/NH/RSC) and the header labels differ between
      them (`PRICE 2026` vs `Price 2026`, and the `name`/`DESCRIPTION` columns swap position).
      Label matching is case- and whitespace-insensitive, so `PRICE 2026` covers both; the column
      ORDER difference is why the map must be by label and never by index.
    - Jim Thompson's FABRIC sheet repeats `H`, `V`, `CM.` and `IN.` in its header. Declaring one of
      those as a column will throw "header carries … more than once" — by design. Use the
      unambiguous labels (`ARTICLE CODE`, `ARTICLE NAME`, `BRAND`, the priced column).
    - `.DS_Store` is present in `incoming/colour-files/`; the converter filters dot-prefixed names.
    - `incoming/` IS populated in this worktree (unlike `incoming/pricing-templates/`, which
      CLAUDE.md notes exists only in the main checkout), so `node scripts/convert-colour-files.js`
      runs here. It still must never be written to.
  - Context: harness `scripts/lib/colour-sheet.js`; registry `scripts/lib/colour-adapters/index.js`;
    driver `scripts/convert-colour-files.js`; tests `test/colour-files.test.js`. The architecture
    section is `_bmad-output/planning-artifacts/architecture.md` "## Colour files".
- **Needs human verification:** none — no screen, no route and no database table is touched by this
  story. The one thing worth a human eye is the console output of
  `npm run convert:colour`, which today lists all 18 drops as unsupported (no adapter is registered
  yet) and exits 1. That is the intended state until US-002/US-003 land.
